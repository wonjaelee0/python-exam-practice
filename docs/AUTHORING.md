# 문제 작성 가이드

문제 1개 = YAML 파일 1개: `content/problems/<단원>/<id>.yaml`
`uv run tools/build.py`가 정답 코드를 실행해 **기대 출력을 자동으로 만든다** (직접 쓰지 않는다).

## 1. 스키마

```yaml
id: b06-dict-count-007        # <단원>-<주제>-<3자리>, 파일 이름과 같게, 바꾸지 않는다
title: 혈액형 빈도수 세기
unit: b06                     # content/units/<unit>.yaml
difficulty: 3                 # 1~5 (아래 기준)
tags: [loop.while-sentinel, dict.count-get]
format: write                 # write(작성) | fill(빈칸 _____) | debug(버그 고치기)
style: elice-main             # elice-main(예시 결과 Input/Output) | elice-pre(TestCase-n) | elice-extra(입력 없음)
statement: |                  # 마크다운. 프롬프트·출력 형식을 글자 그대로 적는다
  ...
starter: |                    # 에디터 초기 코드 (fill이면 _____ 포함)
  ...
solution: |                   # 정답 — Python 3.6 호환, 제출 규칙 준수 (기대 출력의 원천)
  ...
alt_solutions:                # 다른 접근으로 독립 작성한 정답 (모든 테스트에서 같은 출력이어야 함)
  - |
    ...
mutants:                      # 흔한 오답 — 테스트 중 하나는 반드시 틀려야 함
  - name: 평균을 // 로 계산
    code: |
      ...
tests:                        # stdin만 쓴다. expected는 빌드가 만든다
  - stdin: "10\n20\n종료\n"
    public: true              # 지문 아래 '예시 결과'로 보인다
  - stdin: "종료\n"
    note: 숫자 없이 바로 종료  # 틀렸을 때 학생에게 보여 줄 힌트
hints: [힌트1, 힌트2, 힌트3]
explanation: |
  해설
```

## 2. 지문 규칙

- **출력이 지문만으로 완전히 결정되어야 한다.** 프롬프트 문자열, 구분자, 공백, 소수점 자리, 정렬 기준, 예외 메시지를 모두 적는다.
  빌드가 "정답이 출력하는 문구가 지문·공개 예시에 없다"고 경고하면 지문을 보강한다.
- 프롬프트는 `` `이름: ` ``처럼 백틱으로 감싸고 끝 공백까지 쓴다.
- 외부 이미지 링크 금지 (GitHub Pages 교차 출처 격리와 저작권 때문). 그림이 필요하면 직접 만들어 저장소에 넣는다.
- 강의자료·elice 문제의 문장을 그대로 쓰지 않는다. 상황·데이터·문구를 새로 만든다.

## 3. 정답 코드 규칙 (어기면 빌드 실패)

- **Python 3.6 문법**: `f"{x=}"`, f-string 중괄호 안의 같은 따옴표·역슬래시, `:=`, `match`, `str.removeprefix` 등 금지
- **elice 제출 규칙**: `:` 뒤 공백 (`input("이름: ")`, `f"합계: {s}"`), `,` 뒤 공백, 문장부호 앞 공백 없음, random을 쓰면 `random.seed(1)`
- **결정적인 출력**: set을 그대로 출력하지 않는다 (`sorted()` 후 출력). 시드 없는 무작위 금지
- 그 단원까지 배운 문법만 쓴다 (예: b03 문제에 리스트를 요구하지 않는다)

## 4. 테스트 설계

- 공개 1~2개, 숨김 4~6개
- 경계값(0, 1, 최대·최소, 같음), 즉시 `종료`, 빈 입력, 대소문자, 앞뒤 공백, 중복, 동률을 섞는다
- 오답 코드(mutants)는 실제로 학생들이 하는 실수로: 형변환 누락, `/`↔`//`, range 끝값, `>`↔`>=`, elif 순서, 센티넬을 개수에 포함, set 출력 등

## 5. 난이도 기준

| ★ | 기준 |
|---|---|
| 1 | 문법 1개 (입력 → 계산 → 출력) |
| 2 | 개념 2개 조합 |
| 3 | elice 본문제 수준 (반복 + 조건 + 자료구조) |
| 4 | elice 추가문제 수준 (여러 단원 종합) |
| 5 | 고난도 |
